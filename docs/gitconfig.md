# Git configuration

Two files cooperate, on **both** Windows and WSL:

| File | Tracked? | What it holds |
|---|---|---|
| `git/.gitconfig` (this repo) | yes | Shared defaults only: delta as pager, linear-history rebase workflow, merge/diff behavior, aliases. Treat as **read-only** |
| `~/.gitconfig` (each machine) | **no** — a real file generated by the setup scripts | `[include]` of the shared file (always the **first** section), plus everything specific to that machine: identity, credential helper, anything you set later |

```ini
# ~/.gitconfig (generated)
[include]
	path = D:/Workspace/new-windows-setup/git/.gitconfig   # /mnt/d/... in WSL
[user]
	name = Your Name
	email = your@email.com
[credential]
	helper = /mnt/c/Program\\ Files/Git/ucrt64/bin/git-credential-manager.exe   # WSL only
```

Because the include comes first, anything defined locally **overrides** the shared default, and the rest is inherited.

## Why it is not a symlink anymore

`~/.gitconfig` used to be a symlink to the tracked `git/.gitconfig`. That made every `git config --global ...` — typed by hand, run by an IDE, a Claude session, a stale setup copy, or restored by an editor checkpoint — write **straight into the repository**: `[user]` blocks and a `credential.helper` with a machine-specific `/mnt/c/...` path kept showing up as uncommitted changes (and the helper broke whenever Git for Windows renamed its `mingw64` folder to `ucrt64`).

Now `git config --global user.name "..."` is safe: it lands in the local `~/.gitconfig`. Nothing a user or tool does globally can modify the tracked file.

`tests/pester/GitConfig.Tests.ps1` fails if `git/.gitconfig` ever contains a `[user]`, `[credential]` or `[include]` section.

## How the scripts apply it

- **Windows** — `setup-windows.ps1` (`Set-GitConfigInclude`) creates `~/.gitconfig`, or prepends the include to an existing one (backup: `~/.gitconfig.pre-include.bak`). A legacy symlink is replaced by a real file, keeping any identity found in it.
- **WSL** — `provision_git_config` (`wsl/lib/git_config.sh`) does the same, via `setup-wsl.ps1` passing `--repo-path`. It also resolves the Windows Git Credential Manager path dynamically (no hardcoded `mingw64`/`ucrt64`), escaping the space in `Program Files`, and only replaces a `credential.helper` that is unset or points at a path that no longer exists (`store`/`cache` are left alone).
- **Identity** comes from the `Git` block of `windows/windows.config.psd1` (see the [README](../README.md#configuration)). Existing values are **kept**, never overwritten on re-runs. Identity from the previous design's `~/.gitconfig.local` is migrated.
- Running `setup-wsl.sh` standalone (no repo path) applies the same defaults inline into the local `~/.gitconfig`, and still replaces a legacy symlink first so those writes can never reach a repo file.

## Good to know

- `git config --global --get <key>` reads only `~/.gitconfig` itself; plain `git config --get <key>` (all scopes) also sees values inherited through the include.
- `git config --global --unset <key>` cannot remove a value that comes from the shared file (it exits 0 and the inherited value stays). Override it locally instead, e.g. `git config --global pull.rebase false`.
- The shared file lives in `git/` alongside `git-repos.config.psd1` — both are git-related config that other scripts locate by path.
